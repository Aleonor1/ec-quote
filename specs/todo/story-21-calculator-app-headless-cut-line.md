# story-21: [calculator-app] Headless cut line: shared geometry kernel and sync route

**Repository:** `etichetecreative-calculator-app` (NOT ec-quote) · **Epic:** [EPIC-2](epic-2-file-and-mockup.md) · **Depends on:** none in code. Needs the owner's decision EPIC-2 D2 before it starts.

Copy this spec into the calculator app as `docs/spec-crm-cutline.md` before shipping it there. All paths below are in that repository.

## Summary

Today a cut line exists only after a person opened Contur Studio in a browser. The geometry (distance transform, marching squares, joining parts, minimum neck and inner radius, smoothing, fixed shapes, bleed and liner) lives inside the browser script `extensions/calculator/assets/contur-studio.js`, closed over in `mount()` and tied to DOM canvases; the server only builds the production PDF from paths the browser computed (`app/utils/production-pdf.server.ts`). ec-quote and the CRM need the same cut line without a browser. This story moves the geometry into one plain module used by both sides, exactly as was done for `pricing-core.js` and `emboss-trace.js`, and exposes it through a server to server route. The studio's behaviour on the site must not change.

## User Story

As the quoting service, I want the cut line the studio would draw for a file, a size and a shape, computed on the server, so that the mockup and the order show the shape production will really cut.

## Scope

**In:** `app/utils/contour-core.js` (new, plain JS without imports or DOM: the geometry functions and one entry `computeCutline({alpha, width, height, widthMm, heightMm, shape, corners, borderMm, cut})`); `scripts/build-contour-core.mjs` and the generated `extensions/calculator/assets/contour-core.js`; `extensions/calculator/assets/contur-studio.js` (calls the kernel; no behaviour change); `extensions/calculator/blocks/calculator.liquid` and `app/utils/crm-studio.server.ts` plus the `/crm-assets` list (load order); `app/utils/cutline.server.ts` (artwork to alpha mask with `sharp`, PDF and AI page 1 through Ghostscript, calls the kernel, builds the preview); `app/routes/api.sync.cutline.ts`; `app/utils/production-pdf.server.ts` (its duplicate `smoothPolys` replaced by the kernel's); tests under `tests/utils/`, `tests/routes/`, `tests/storefront/`; `docs/spec-crm-sync.md`, `CHANGELOG.md`.

**Out:** background removal on the server (an opaque image gets a shape cut, see criterion 7); emboss zones; any change to what the studio shows or to the proof format; the production PDF's layout; ec-quote's client (story-22).

## Acceptance Criteria

1. `app/utils/contour-core.js` has no reference to `window`, `document`, canvas or any import, and runs under Node; the storefront copy is generated by `scripts/build-contour-core.mjs` and a test fails when the two differ, as for `pricing-core.js`.
2. `contur-studio.js` contains no second implementation of the moved functions (`edt`, `contours`, `polysMm`, `smoothPolys`, `shapePolys`, `fillHoles`, component joining, `thinParts`); a test greps for their definitions. `ConturStudio.lib` keeps exposing the helpers its existing tests use.
3. Every existing test passes unchanged: `tests/storefront/contur-studio-lib.test.ts`, `tests/crm-studio/*`, the production PDF tests and the e2e specs' page objects. The proof JSON the studio builds for the fixtures of `tests/crm-studio/page.integration.test.ts` is identical before and after (snapshot taken on the base branch).
4. `POST /api/sync/cutline` with `X-Sync-Secret` and `{fileUrl, widthCm, heightCm, shape, corners?, cut?, borderMm?}` answers 200 `{status: "ok", kind: "contour" | "shape", design, paths: {cut, bleed, liner}, previewUrl | previewPng, warnings: []}` with geometry in millimetres in the `ProofData` convention (design at 0,0, y down); without the secret 401; other methods 405; an invalid body 400 with `fields`.
5. `fileUrl` must be under the app's own storage base URL (the guard of `artwork-inspect`); anything else answers 400 and nothing is fetched.
6. Parity: for at least 8 fixtures (transparent PNG logo, PNG with separate parts closer and farther than the join distance, a shape with a neck thinner than 4 mm, a circle, an SVG, a vector PDF, a JPEG, an image smaller than the minimum design size) the route's `paths.cut` and the studio's proof `paths.cut` for the same inputs (studio run in jsdom with `tests/helpers/canvas-shim.ts`) agree within 0.1 mm Hausdorff distance, and have the same number of closed loops.
7. An image with no usable transparency (alpha unused or an opaque uniform background) returns `kind: "shape"` with the requested shape (`rectangle`, `square`, `circle`, `oval`, with `corners`), never a traced contour, and the warning `opaque_background`; `shape: "custom"` on such an image answers 422 `{status: "no_contour", reason: "opaque_background"}`.
8. Production rules hold in the output of every contour fixture: one outer loop, no interior holes cut, no neck under 4 mm, inner corner radius at least 2 mm (checked numerically on the returned path).
9. `buildProductionPdf` fed with a `ProofData` assembled from the route's response for one fixture produces a PDF whose Thru-cut path equals the route's `paths.cut` after Bézier fitting within the existing tolerance.
10. Limits and failures: a file over 25 MB, a raster over the pixel cap, a PDF that Ghostscript cannot render, a download failure and a timeout each give a 4xx or 502 with an error code and no stack; processing one request is bounded by a timeout; the route makes no write to Shopify.
11. The route answers in under 5 seconds for a 3000 px PNG on the reference machine of the tests (asserted with a generous bound on the kernel alone).
12. `npm run lint`, `npm run typecheck`, `npm test` green; the extension still passes `shopify app build`.

## Technical Notes

- Follow the precedent exactly: `app/utils/emboss-trace.js` is the source of truth and `scripts/build-emboss-trace.mjs` generates the storefront asset; the kernel must load before `contur-studio.js` in the block and in `CRM_STUDIO_SCRIPTS`.
- The studio works on a millimetre grid capped at `WORK_MAX_PX`; the server adapter must build the same grid from `sharp` raw RGBA (`ensureAlpha().raw()`), including the automatic trim of transparent margins, or parity fails.
- PDF and AI: page 1 rasterized by Ghostscript with transparency (`pngalpha`), as `production-pdf.server.ts` already does; `sharp` cannot read PDF.
- Background removal in the studio is a browser model (transformers.js, WebGPU or WASM). Running it on the server is a separate decision and a separate story.
- The storefront asset changes, so this story needs both a server deploy and `shopify app deploy --allow-updates`.
